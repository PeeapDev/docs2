# Sign in with Peeap (OAuth 2.0)

Use OAuth when you want **Peeap users** to sign in to your app and optionally
grant access to their profile or wallet — a "Sign in with Peeap" button. This is
separate from your [secret API key](/api-reference/auth/api-keys), which
authenticates *your own* account's money.

Your app authenticates with a `client_id` + `client_secret` (registered in the
dashboard) and receives a per-user `access_token` scoped to what the user
approved.

## Scopes

| Scope | Grants |
|-------|--------|
| `profile` | Name |
| `email` | Email address |
| `phone` | Phone number |
| `wallet:read` | Read the user's wallet balance |
| `wallet:write` | Initiate wallet actions on the user's behalf |

## Exchange a code for tokens

```
POST /oauth/token
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `grant_type` | string | Yes | `authorization_code` or `refresh_token` |
| `client_id` | string | Yes | Your app's client id |
| `client_secret` | string | Yes | Your app's client secret |
| `code` | string | For `authorization_code` | One-time code from the redirect |
| `redirect_uri` | string | For `authorization_code` | Must match the code exactly |
| `refresh_token` | string | For `refresh_token` | Rotates to a fresh token |

### Response (200)

```json
{
  "access_token": "…",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "…",
  "scope": "profile email wallet:read",
  "user": { "peeap_id": "…", "email": "jane@example.com", "name": "Jane Doe", "is_new_account": false },
  "wallet": { "wallet_id": "…", "balance": 0, "currency": "SLE", "status": "active" }
}
```

`user` is included when the code resolves to a user; `wallet` is included when the
granted scope includes `wallet:read`/`wallet:write`.

### Errors

`400 invalid_request` · `401 invalid_client` · `400 invalid_grant` (bad/expired/used
code) · `400 unsupported_grant_type`. All error bodies carry `error` +
`error_description`.

## Get the signed-in user

```
GET /oauth/userinfo
```

Send `Authorization: Bearer <access_token>`. Returns claims gated by scope:

```json
{
  "sub": "user-uuid",
  "name": "Jane Doe",
  "given_name": "Jane",
  "family_name": "Doe",
  "email": "jane@example.com",
  "phone": "+23276123456"
}
```

`sub` is always present; `name` requires `profile`, `email` requires `email`,
`phone` requires `phone`. Errors: `401 invalid_token`, `404 not_found`.

## Revoke a token

```
POST /oauth/revoke
```

Body `{ "token": "…", "token_type_hint": "access_token" | "refresh_token" }`.
Always returns `200 { "success": true }` (even if the token was already gone).
