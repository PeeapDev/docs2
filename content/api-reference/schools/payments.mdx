# School Payments API

Charge a student's Peeap wallet — for canteen purchases, vendor sales, or school
fees — using a two-step **initiate → authorize** flow. The first call creates a
pending payment session; the second verifies the student's PIN and moves the
money atomically from the student wallet to the vendor (or school) wallet.

<Note>
These endpoints authenticate with a **school integration token** — the Bearer
token issued to your school when it connects to Peeap (see
[Peeap Integration](/api-reference/schools/peeap-integration)). Every request is
scoped to your school; a session for a student at another school is rejected.
</Note>

## Auth

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer {SCHOOL_TOKEN}` |
| `Content-Type` | `application/json` |

Students are identified by their **NSI** (National Student Index) — a letter
followed by 6 digits, e.g. `A123456`.

## Step 1 — Initiate a payment

Creates a pending payment session against the student's wallet.

```
POST /school/payments/initiate
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `nsi` | string | Yes | Student NSI (e.g. `A123456`) |
| `vendor_id` | string | Yes | The vendor receiving the payment (must belong to your school) |
| `amount` | number | Yes | Amount in SLE, must be greater than 0 |
| `description` | string | No | Line description (defaults to `"{vendor} purchase"`) |
| `items` | array | No | Optional itemized list `[{ name, qty, price }]` |
| `currency` | string | No | Defaults to `SLE` |

### Example Request

```bash
curl -X POST https://api.peeap.com/school/payments/initiate \
  -H "Authorization: Bearer YOUR_SCHOOL_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "nsi": "A123456",
    "vendor_id": "canteen-01",
    "amount": 15000,
    "description": "Lunch - Rice & Chicken"
  }'
```

### Success Response (200)

```json
{
  "success": true,
  "data": {
    "session_id": "ps_9f2c8b1a4d7e4c6f",
    "nsi": "A123456",
    "vendor_id": "canteen-01",
    "vendor_name": "Campus Canteen",
    "amount": 15000,
    "currency": "SLE",
    "expires_at": "2026-07-08T10:10:00Z",
    "status": "pending"
  }
}
```

### Errors

| Status | `error` | Meaning |
|--------|---------|---------|
| 400 | `invalid_request` | Missing/invalid `nsi`, `vendor_id`, or `amount ≤ 0` |
| 401 | `unauthorized` | Missing or invalid school token |
| 403 | `wrong_school` | Student belongs to a different school |
| 404 | `wallet_not_found` / `vendor_not_found` | Unknown student or vendor |
| 409 | `wallet_not_active` / `vendor_inactive` / `vendor_has_no_wallet` | Wallet or vendor not usable |

## Step 2 — Authorize with the student PIN

The student enters their PIN on the vendor device. This verifies the PIN, debits
the student wallet, and credits the vendor wallet **atomically** (idempotent on
`session_id`).

```
POST /payments/authorize
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `session_id` | string | Yes | The `session_id` from step 1 |
| `pin` | string | Yes | The student's transaction PIN |

### Example Request

```bash
curl -X POST https://api.peeap.com/payments/authorize \
  -H "Authorization: Bearer YOUR_SCHOOL_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "ps_9f2c8b1a4d7e4c6f",
    "pin": "1234"
  }'
```

### Success Response (200)

```json
{
  "success": true,
  "data": {
    "session_id": "ps_9f2c8b1a4d7e4c6f",
    "transaction_id": "txn_7b3e9a12",
    "status": "authorized",
    "amount": 15000,
    "currency": "SLE"
  }
}
```

On success, Peeap fires a `transaction.completed`
[webhook](/api-reference/schools/peeap-integration) to your school.

### Errors

| Status | `error` | Meaning |
|--------|---------|---------|
| 401 | `pin_invalid` | Wrong PIN — response includes `attempts_remaining` |
| 404 | `session_not_found` / `wallet_not_found` | Unknown session or wallet |
| 409 | `session_not_pending` | Session already used, expired, or cancelled |
| 409 | `insufficient_funds` | Student wallet balance too low (from the ledger) |
| 410 | `session_expired` | Session TTL elapsed — start a new one |
| 412 | `pin_not_set` | Student has never set a PIN |
| 423 | `pin_locked` | Too many wrong PINs — includes `locked_until` |

## One-call alternative — charge a scanned card

When a vendor scans the student's NFC card in the Peeap app (rather than driving
a terminal via the school token), use the **merchant** endpoint. It resolves the
student, checks the PIN, and moves money in a single call.

```
POST /merchant/charge-student
```

Authenticated as the **logged-in vendor/merchant** (user session Bearer token),
not the school token.

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `nsi` | string | One of `nsi` / `studentWalletId` | Student NSI |
| `studentWalletId` | string | One of `nsi` / `studentWalletId` | Wallet id carried on a scanned card |
| `amount` | number | Yes | Amount in SLE, greater than 0 |
| `pin` | string | Conditional | Required unless the student's parent set `require_pin=false` |
| `items` | array | No | Itemized list |
| `description` | string | No | Line description |
| `idempotencyKey` | string | No | De-duplicate retries |
| `currency` | string | No | Defaults to `SLE` |

<Warning>
`merchant/charge-student` moves money immediately on a correct PIN. Always send
an `idempotencyKey` so a network retry can't double-charge the student. Charges
are bounded by the student's `daily_limit`.
</Warning>

## Paying school fees to the school (SaaS)

To record a **fee payment** against the school's own fee ledger (tuition, bus,
etc.), post to the fees endpoint. Peeap forwards the request to the connected
school system.

```
POST /school/fees/pay
```

NSI fields are normalized and forwarded to the school's `/pay-fee` handler; the
school system's response (receipt, remaining balance) is returned verbatim.

<Info>
Two different "fees" concepts:
- **Canteen / vendor purchases** → `initiate` + `authorize` (money moves between
  Peeap wallets).
- **Tuition / school fees** → `/school/fees/pay` (recorded in the school's fee
  ledger via the SaaS).
</Info>
