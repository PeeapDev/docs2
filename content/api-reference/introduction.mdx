# API Reference

The Peeap API is organized around REST. It accepts JSON request bodies, returns
JSON responses, and uses standard HTTP status codes. All amounts are in **SLE**
(Sierra Leonean Leone), the platform settlement currency.

## Base URL

```
https://api.peeap.com
```

## Authentication

Peeap uses three credentials, depending on what you're doing:

| Credential | Header | Use |
|------------|--------|-----|
| **Secret key** `sk_live_…` / `sk_test_…` | `Authorization: Bearer sk_…` | Your account's money — [balance](/api-reference/wallet/balance), [transactions](/api-reference/wallet/transactions), [payouts](/api-reference/wallet/payouts), [webhooks](/api-reference/webhooks/manage) |
| **Publishable key** `pk_live_…` / `pk_test_…` | In the request body | [Create a checkout](/api-reference/checkout/create) link |
| **OAuth access token** | `Authorization: Bearer <token>` | [Sign in with Peeap](/api-reference/auth/oauth) — act on a user's behalf |

Test keys (`_test_`) run in a sandbox where no real money moves; live keys settle
for real. See [Authentication](/api-reference/auth/api-keys).

<Warning>
Secret keys move money — keep them server-side. Publishable keys (`pk_…`) are the
only keys safe to expose in a checkout link, and they cannot read balances or
send payouts.
</Warning>

## Response envelope

The `/v1/*` money endpoints use a consistent envelope:

```json
{ "success": true, "data": { "...": "..." }, "timestamp": "2026-07-08T10:00:00.000Z" }
```

```json
{ "success": false, "error": { "code": "UNAUTHORIZED", "message": "…" }, "timestamp": "…" }
```

List endpoints add a `meta` block:

```json
{ "success": true, "data": [ "..." ],
  "meta": { "page": 1, "limit": 20, "total": 137, "total_pages": 7, "has_next_page": true, "has_previous_page": false } }
```

<Note>
Checkout, verify, cards, and school endpoints predate the `/v1` envelope and
return their fields at the top level (documented per endpoint). When in doubt,
the shape shown on each endpoint page is the real one.
</Note>

## Idempotency

Money-moving POSTs accept — and [payouts](/api-reference/wallet/payouts)
**require** — an `Idempotency-Key` header so a retried request never sends money
twice.

```
Idempotency-Key: payout-2026-07-08-0001
```
