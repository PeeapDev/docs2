# Chapter 11 · Webhooks

A webhook is Peeap calling **you**: instead of your server polling
"is it paid yet?", Peeap POSTs your server the moment something happens. It's the
ideal way to learn about a completed payment — and it's wired up today.

## Status today

<Note>
**`payment.completed` fires on every completion path.** Whether the customer
pays by mobile money, USSD, card, scan-to-pay / QR, NFC tap, or at a POS
terminal, the settlement code emits the event to your registered endpoint the
moment your wallet is credited. Two more events cover money going out:
`payout.completed` and `payout.failed`. Those three are the complete list —
don't build against any other event name.
</Note>

A webhook is still a *notification*, not a source of truth: endpoints go down,
retries exhaust, databases get restored from backups. Keep your reconciler
([Chapter 10](/guide/reconciliation)) running — the webhook makes you fast, the
reconciler keeps you correct.

<Note>
**School integrations use a separate delivery path.** If you're building a
school system, Peeap POSTs events (`fee.paid`, `invoice.paid`,
`transaction.completed`) to a registered school endpoint, signed with
`X-Peeap-Signature: sha256=<hmac>`. See the
[school fees recipe](/guide/recipe-school-fees) and
`SCHOOL_API_DOCUMENTATION.md`. The rest of this chapter is about the *general
merchant* webhook system.
</Note>

## Registering an endpoint

Register a URL and the events you care about, authenticated with your secret
key. (Alternatively, paste the URL into **Business Settings** — it flows into
the same managed system, subscribed to all three events.)

```http
POST https://api.peeap.com/v1/webhooks
Authorization: Bearer sk_live_YOUR_SECRET_KEY
Content-Type: application/json
```

```json
{
  "url": "https://yourstore.com/webhooks/peeap",
  "events": ["payment.completed"]
}
```

The response includes a **signing secret**, shown **once**:

```json
{
  "id": "3f7c9a2e-...",
  "url": "https://yourstore.com/webhooks/peeap",
  "events": ["payment.completed"],
  "created_at": "2026-07-14T10:00:00.000Z",
  "secret": "whsec_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

<Note>
Copy the `whsec_…` secret immediately and store it like a password — it isn't
shown again. You'll use it to verify that incoming webhooks are genuinely from
Peeap. `GET /v1/webhooks` lists your endpoints (without secrets);
`DELETE /v1/webhooks/:id` deactivates one. There is no update endpoint — to
change events or rotate the secret, delete and re-create.
</Note>

## The delivery format

When an event fires, Peeap sends an HTTP `POST` to your URL with:

- **Header** `X-Webhook-Signature: t=<unix seconds>,v1=<signature>`
- **Header** `X-Webhook-Id` — stable across retries; your dedupe key
- **Headers** `X-Webhook-Event` and `X-Webhook-Attempt`
- **Body** `{ "id": "...", "type": "payment.completed", "created": <unix seconds>, "data": { ... } }`

For `payment.completed`, `data` is
`{ id, reference, amount, currency, status: "completed", payment_method }`,
where `id` is the checkout session id and `reference` is yours from create.

Peeap **retries** failed deliveries (non-2xx, or no response within 10 seconds)
with backoff — 1 minute, 5 minutes, 25 minutes, 2 hours, then 10 hours — for up
to **6 attempts total** before parking the delivery permanently. Retries can
overlap a slow first attempt, so your handler must tolerate receiving the same
event more than once — dedupe on `X-Webhook-Id` and be idempotent
([Chapter 8](/guide/idempotency)).

## Verifying the signature (do this on every webhook)

A webhook endpoint is a public URL — anyone can POST to it. **Never act on a
webhook you haven't verified.** Peeap signs each delivery with HMAC-SHA256 over the
string `"{timestamp}.{rawBody}"`, using your `whsec_…` secret. The timestamp is
Unix **seconds**; reject anything more than 300 seconds from your clock.

<CodeGroup>

```javascript Node.js / Express
import crypto from "crypto";

// IMPORTANT: verify against the RAW body, before any JSON parsing/reserialising.
app.post(
  "/webhooks/peeap",
  express.raw({ type: "application/json" }),
  (req, res) => {
    const header = req.headers["x-webhook-signature"]; // "t=...,v1=..."
    const secret = process.env.PEEAP_WEBHOOK_SECRET;    // whsec_...

    const parts = Object.fromEntries(
      header.split(",").map((kv) => kv.split("="))
    );

    // Replay window: t is unix SECONDS, allow 300s of skew.
    if (Math.abs(Math.floor(Date.now() / 1000) - Number(parts.t)) > 300) {
      return res.status(400).send("stale timestamp");
    }

    const signedPayload = `${parts.t}.${req.body.toString("utf8")}`;

    const expected = crypto
      .createHmac("sha256", secret)
      .update(signedPayload)
      .digest("hex");

    const ok =
      expected.length === parts.v1.length &&
      crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1));

    if (!ok) return res.status(400).send("bad signature");

    // Verified. Dedupe on the delivery id, then ACK fast.
    const deliveryId = req.headers["x-webhook-id"];
    const event = JSON.parse(req.body.toString("utf8"));
    handleEventOnce(deliveryId, event); // idempotent; do real work async
    res.status(200).send("ok");
  }
);
```

```python Python / Flask
import hmac, hashlib, os, time
from flask import request, abort

@app.post("/webhooks/peeap")
def peeap_webhook():
    header = request.headers.get("X-Webhook-Signature", "")  # "t=...,v1=..."
    secret = os.environ["PEEAP_WEBHOOK_SECRET"]              # whsec_...

    parts = dict(kv.split("=") for kv in header.split(","))

    # Replay window: t is unix SECONDS, allow 300s of skew.
    if abs(int(time.time()) - int(parts["t"])) > 300:
        abort(400)

    raw = request.get_data(as_text=True)                    # RAW body
    signed = f"{parts['t']}.{raw}"

    expected = hmac.new(secret.encode(), signed.encode(), hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, parts["v1"]):
        abort(400)

    # Verified — dedupe on the delivery id, then return 200 quickly.
    delivery_id = request.headers.get("X-Webhook-Id")
    handle_event_once(delivery_id, request.get_json())
    return "ok", 200
```

</CodeGroup>

<Warning>
**Three rules for webhook handlers:**
1. **Verify against the raw body.** Re-serialising the JSON changes the bytes and
   breaks the signature. Capture the raw request body before parsing.
2. **Use a constant-time compare** (`timingSafeEqual` / `compare_digest`), never
   `==`, to avoid timing attacks.
3. **Respond `200` fast (within 10 seconds) and do the work idempotently, keyed
   on `X-Webhook-Id`.** Slow handlers trigger retries — and retries mean you'll
   see the same event twice.
</Warning>

## Recommended pattern: webhook *and* reconciler

The robust production setup uses both:

- **Webhook (the fast path)** — when it fires, treat it as "check this session
  now": look up the session, run the *same* idempotent fulfilment your reconciler
  uses. The webhook makes you faster; it never bypasses your verification.
- **Reconciler (the safety net)** — catches anything a webhook misses: a parked
  delivery, an outage on your side, a restored database. With
  [`GET /v1/payments`](/guide/reconciliation) you can now diff your ledger
  against Peeap's list of your payments directly.

That way a dropped webhook costs you minutes of latency, never a lost payment.
