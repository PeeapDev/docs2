# Webhook Events

Peeap delivers exactly **three** event types today. Every delivery uses the
same envelope:

```json
{
  "id": "b4d1f8e2-3c6a-4f9b-8e2d-7a5c1f4b9e3d",
  "type": "payment.completed",
  "created": 1752487200,
  "data": { }
}
```

- `id` — unique event id
- `type` — one of the event names below
- `created` — Unix timestamp in **seconds**
- `data` — the event object

<Note>
For deduplication, use the `X-Webhook-Id` **header** — it is stable across
retries of the same delivery.
</Note>

## payment.completed

Sent when an incoming payment settles and your wallet is credited. This fires
on **every** completion rail: mobile money, USSD, card, scan-to-pay / QR, NFC
tap, and POS.

```json
{
  "id": "b4d1f8e2-3c6a-4f9b-8e2d-7a5c1f4b9e3d",
  "type": "payment.completed",
  "created": 1752487200,
  "data": {
    "id": "cs_a1b2c3d4",
    "reference": "order_1042",
    "amount": 150.00,
    "currency": "SLE",
    "status": "completed",
    "payment_method": "mobile_money"
  }
}
```

| Field | Description |
|-------|-------------|
| `id` | The checkout session id (the same id you got when creating the session) |
| `reference` | Your reference from session creation, or `null` |
| `amount` | Amount paid, in SLE |
| `currency` | Currency code (`SLE`) |
| `status` | Always `"completed"` for this event |
| `payment_method` | The rail the customer paid on, e.g. `mobile_money`, `ussd`, `peeap_card`, `scan_to_pay` |

## payout.completed

Sent when a payout you initiated reaches its destination.

```json
{
  "id": "c7e2a9f4-1b8d-4e3c-9f6a-2d5b8e1c4a7d",
  "type": "payout.completed",
  "created": 1752490800,
  "data": {
    "id": "po_e5f6g7h8",
    "amount": 500.00,
    "fee": 10.00,
    "currency": "SLE",
    "status": "completed",
    "destination": { "type": "momo", "provider": "Orange Money" },
    "failure_message": null
  }
}
```

| Field | Description |
|-------|-------------|
| `id` | The payout id |
| `amount` | Payout amount, in SLE |
| `fee` | Fee charged (may be absent when the payout settles asynchronously) |
| `currency` | Currency code (`SLE`) |
| `status` | Always `"completed"` for this event |
| `destination` | `{ type, provider }` (may be absent on asynchronous settlement) |
| `failure_message` | Always `null` for this event |

## payout.failed

Sent when a payout fails. The debited funds are automatically refunded to your
wallet.

```json
{
  "id": "d9f4b1e7-6c2a-4a8e-b3d5-8f1c4e7a2d5b",
  "type": "payout.failed",
  "created": 1752491100,
  "data": {
    "id": "po_e5f6g7h8",
    "amount": 500.00,
    "currency": "SLE",
    "status": "failed",
    "failure_message": "Recipient account not found"
  }
}
```

| Field | Description |
|-------|-------------|
| `id` | The payout id |
| `amount` | Payout amount, in SLE |
| `currency` | Currency code (`SLE`) |
| `status` | Always `"failed"` for this event |
| `failure_message` | Why the rail rejected the payout, or `null` |

## Subscribing to Events

Specify events when registering, or omit `events` to receive all three:

```bash
curl -X POST https://api.peeap.com/v1/webhooks \
  -H "Authorization: Bearer sk_live_YOUR_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-server.com/webhooks/peeap",
    "events": ["payment.completed", "payout.failed"]
  }'
```

Endpoints registered via **Business Settings** are subscribed to all three
events automatically.

## Roadmap

<Note>
Events for refunds, KYC status changes, and card lifecycle are under
consideration but are **not available today**. Only the three events on this
page are delivered — do not build against any other event name.
</Note>
